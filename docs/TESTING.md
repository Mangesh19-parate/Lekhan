# TESTING.md

Goal: nobody should discover a wrong clause, a broken Marathi conjunct or a cross-tenant leak after a deed is signed. Tests are the safety net for both code **and templates**.

---

## 1. Data policy (non-negotiable)
- **Synthetic data only** in repo, fixtures, CI, screenshots and bug reports. Fake names in Marathi and English, invalid-by-construction IDs (for example Aadhaar-like numbers failing the checksum), fictional addresses.
- The private sample archive lives outside the repo (`samples-private/`, git-ignored). CI never has access to it.
- A pre-commit hook and CI job run the leftover/PII scanner over the diff and fail on real-looking identifiers.

## 2. Test pyramid and tools

| Layer | Tool | Scope | Run |
|---|---|---|---|
| Unit | pytest | Pure domain logic | Every commit |
| Property-based | Hypothesis | Number-to-words, units, DAG order, diff, state machines | Every commit (fast profile), nightly (long profile) |
| Template golden | pytest + custom helpers | Every approved template | Every commit that touches templates; always in CI |
| API | pytest + httpx, Schemathesis | Endpoints, auth matrix, tenant isolation | Every commit |
| Integration | pytest + docker compose | Postgres, storage, LibreOffice | Every PR |
| E2E | Playwright | Wizard, forms, generation, download | Every PR (smoke), nightly (full) |
| Frontend unit | Vitest + Testing Library | Components, form logic | Every commit |
| Layout parity | PDF to image comparison | Selected templates | Nightly and on template change |
| Security | OWASP ZAP baseline, `pip-audit`, `npm audit`, Bandit | Whole app | Weekly and before release |
| Performance | k6 or Locust | Generation endpoint, search | Before release |
| Resilience | Scripts | Kill converter, fill disk, drop DB | Before release |
| Mutation | mutmut | DSL evaluator, fee rules | Weekly |

## 3. Commands
```bash
make check          # ruff, mypy --strict, import-linter, pytest -q -m "not slow", eslint, tsc
make test           # backend full
make test-golden    # templates only
make test-property  # Hypothesis long profile
make e2e            # Playwright
make test-security  # pip-audit, bandit, npm audit
make bench          # k6 smoke on generation
```
Coverage target: 85% lines on `domain` and `application` code; 100% on the DSL, authorisation policy and numbering. Coverage is a floor, not a goal; mutation score and golden tests matter more.

## 4. What to test, by area

### 4.1 Condition DSL
- Conformance vectors in `conformance/dsl.json` (expression, inputs, expected, expected error). Never change an expected value to make a test pass without a design note.
- Property tests: parsing then pretty-printing then parsing is stable; evaluation terminates for any generated AST within limits; type errors are compile-time.
- Mutation testing: score tracked; fail the weekly job below the agreed threshold.

### 4.2 Language packs
- **Amount in words:** write the inverse parser (words to number) as a test oracle; property `parse(words(n)) == n` over 0-1,000,000 exhaustively and random larger values with `Decimal`; the company signs off a table of 200 known amounts per language.
- **Dates:** known-value table; month names in Marathi; leap years.
- **Grammar combinations:** for each grammar-sensitive template: 1 male, 1 female, 2 males, 2 females, mixed, 3+ parties; reviewed by the lawyer; stored as golden outputs.
- **Unicode:** NFC normalisation, grapheme-cluster length and truncation on a corpus of conjunct-heavy strings; ZWJ/ZWNJ cases.

### 4.3 Units and money
`Decimal` and exact rationals; round trips (sqft to sqm to sqft within defined tolerance); hectare-R and guntha constants agreed with the company; no floats anywhere (a lint rule bans `float(` in these modules).

### 4.4 Kruti converter
- Corpus regression: round-trip score over the Kruti sample files, computed **locally** (not in CI), published as a number and a list of file ids only.
- Synthetic Kruti fixtures committed for CI (generated by the reverse mapping) covering each variant table, reordering rules, half forms, and Latin-in-Kruti runs.
- Targeted tests for known artefact classes: dangling half letters, stray combining marks, reph placement with conjuncts, pre-base i-matra.

### 4.5 Template lint and compiler
Fixtures for: split-run tag, undefined tag, unused field, macro-enabled file, external relationship, oversized or zip-bomb file, leftover names and IDs, cyclic dependency, missing font. Each must produce the exact expected finding.

### 4.6 Generation pipeline
- Golden tests: for each template and language, fixed synthetic input produces a DOCX; compare extracted text, paragraph count, table count, section properties, fonts, footer fields (PAGE present, no typed page numbers), and the absence of `{{`, `{%`.
- Reopen output with python-docx; validate with the docx validation tools; **manual release step:** open a sample of outputs in real Microsoft Word (LibreOffice is more forgiving).
- Determinism: identical input gives an identical `output_hash`.
- Concurrency: 50 parallel creators produce document numbers 1..50 with no gaps or duplicates; two workers never claim the same job; double-submit with the same `Idempotency-Key` yields one document.
- Failure injection: kill the converter mid-run (state resumes), fill the disk (clean failure, no partial file), drop DB connection (retry).

### 4.7 Authorisation and tenancy
Table-driven matrix test for every endpoint and role; cross-tenant `404`; IDOR attempts; CSRF absent or wrong; throttling and lockout; session fixation and rotation; template submitter cannot approve their own version.

### 4.8 Frontend
- Component tests for repeaters (min/max, renumbering, undo), masks, dual-script fields, status chips (icon + text, not colour only).
- E2E: wizard to generated DOCX for each Wave 1 template (synthetic data), in English and Marathi UI.
- Accessibility: axe checks in Playwright, keyboard-only walkthrough, focus visible, form errors announced.
- Visual: Marathi strings do not truncate or overflow; no negative letter-spacing on Devanagari.

### 4.9 Layout parity
Render the original (with the licensed Kruti font) and the new template to images; compare per clause line breaks and page counts; deviations recorded per template and accepted by the lawyer.

### 4.10 Performance and resilience
Targets: DOCX p95 under 3 s; PDF p95 under 10 s; search p95 under 300 ms at 100k parties (synthetic). Drills: converter crash, storage unavailable, DB failover, worker restart, large upload, burst of 30 generation requests per minute.

### 4.11 Backup and restore
Weekly automated restore into a scratch database; run a smoke query set (counts, latest document, audit chain verify). Before go-live: a full manual drill timed against the 4-hour RTO.

## 5. Template definition of done
A template is releasable only when all hold:
- [ ] Manifest valid; compiler and DOCX lint clean (including leftover-data scan)
- [ ] Golden tests for each language and grammar combination
- [ ] Parity images accepted; page count recorded
- [ ] Amount, date and unit examples signed off
- [ ] Lawyer approval recorded in the system (approver not the submitter)
- [ ] Version is immutable; file hash stored

## 6. UAT script (per wave)
1. Each pilot drafter creates three documents from synthetic matters using a printed checklist.
2. They note time taken, errors, confusing steps.
3. The lawyer reviews outputs against the checklist and logs corrections as numbered items.
4. Exit when corrections per draft fall below the agreed threshold for two consecutive sessions.

## 7. Release gates
No release with: failing tests, an unreviewed OpenAPI breaking change, a high-severity security finding, an unapproved template in the catalogue, a missing restore drill, or real personal data found in repository history.

## 8. Writing good tests with agents
- Ask the agent for the failing test first, then the fix.
- Reject tests that only assert "no exception" or that copy expected values from the output being tested.
- Keep fixtures small and readable; name them for the rule they prove ("two_female_sellers_plural_verb").
