# API.md

REST over HTTPS, JSON, OpenAPI 3 generated by FastAPI (served at `/api/docs` in dev only). Base path: **`/api/v1`**.

---

## 1. Conventions

| Topic | Rule |
|---|---|
| Auth | Cookie session (`lekhan_session`, HTTP-only, Secure, SameSite=Lax). State-changing requests also send `X-CSRF-Token` |
| Ids | UUID strings (opaque; never an authorisation control) |
| Content type | `application/json; charset=utf-8`; file downloads use their MIME type |
| Language | `Accept-Language: mr` or `en` controls error message language; document language is a separate field |
| Errors | `application/problem+json` (RFC 9457 style) with `code`, `detail`, `correlation_id`, optional `errors[]` |
| Pagination | Cursor: `?limit=25&cursor=<opaque>`; response `{ "items": [], "next_cursor": null }` |
| Concurrency | `ETag` on GET of mutable resources; `If-Match` required on PUT/PATCH/DELETE; mismatch gives `412` |
| Idempotency | `Idempotency-Key` header **required** on `POST /documents` and other job-creating calls |
| Dates | ISO 8601 in UTC for timestamps; business dates `YYYY-MM-DD` |
| Money | Strings with two decimals (`"1310000.00"`), never floats |
| Rate limits | 5 login attempts per 15 min per account and IP; 30 generation requests per minute per user; `429` with `Retry-After` |
| Versioning | `/api/v1` is stable; breaking changes go to `/api/v2` |
| Tenancy | Resolved from the session; never accepted from the client |

### Error shape
```json
{
  "type": "https://lekhan.local/errors/validation",
  "title": "Validation failed",
  "status": 422,
  "code": "VALIDATION_ERROR",
  "detail": "Advance cannot exceed total consideration.",
  "correlation_id": "01HX...",
  "errors": [{ "path": "financial.advance", "code": "MAX_EXCEEDED", "message": "..." }]
}
```

### Error codes
| HTTP | `code` | Meaning |
|---|---|---|
| 400 | `BAD_REQUEST` | Malformed request |
| 401 | `UNAUTHENTICATED` | No or expired session |
| 403 | `FORBIDDEN` | Role or policy denies the action |
| 404 | `NOT_FOUND` | Also returned for resources in another tenant |
| 409 | `CONFLICT` | State conflict (for example illegal workflow transition) |
| 412 | `PRECONDITION_FAILED` | `If-Match` version mismatch |
| 413 | `UPLOAD_TOO_LARGE` | File exceeds limit |
| 415 | `UNSUPPORTED_MEDIA` | Not a DOCX, macros present |
| 422 | `VALIDATION_ERROR` | Field or rule validation failed |
| 423 | `LOCKED` | Account temporarily locked |
| 429 | `RATE_LIMITED` | Too many requests |
| 500 | `INTERNAL` | Unexpected; includes `correlation_id` |
| 503 | `DEPENDENCY_UNAVAILABLE` | Converter or storage unavailable |

## 2. Endpoints

Legend: roles A = admin, T = template_admin, R = reviewer, D = drafter. All endpoints are tenant-scoped.

### 2.1 Auth and session (see AUTH.md)
| Method and path | Roles | Purpose |
|---|---|---|
| `POST /auth/login` | public | Email + password (+ `totp` when enabled); sets cookies |
| `POST /auth/logout` | any | Destroys session |
| `GET /auth/me` | any | Current user, role, tenant, UI language, CSRF token |
| `POST /auth/password/change` | any | Change password (requires current) |
| `POST /auth/password/forgot` | public | Sends reset email (always `202`) |
| `POST /auth/password/reset` | public | Completes reset with token |
| `POST /auth/mfa/enroll` / `verify` / `disable` | any | TOTP lifecycle |

### 2.2 Users and settings
| Method and path | Roles | Purpose |
|---|---|---|
| `GET /users` | A | List users |
| `POST /users` | A | Create user (temporary password, forced change) |
| `PATCH /users/{id}` | A | Change role, active flag, language |
| `GET /settings` / `PATCH /settings` | A | Tenant settings (digits preference, numbering format, retention days) |

### 2.3 Catalog and wizard
| Method and path | Roles | Purpose |
|---|---|---|
| `GET /catalog/options?language=mr` | any | Property types and document types that have an **Approved** template for that language |
| `GET /catalog/options?language=mr&property=plot` | any | Document types for the chosen property type |

### 2.4 Templates
| Method and path | Roles | Purpose |
|---|---|---|
| `GET /templates` | any | List templates (filters: `doc_type`, `language`, `status`) |
| `POST /templates` | T | Create template shell |
| `POST /templates/{id}/versions` | T | Upload DOCX + manifest (multipart); runs compile and lint |
| `GET /templates/{id}/versions/{v}` | T, R | Version detail with `lint_report` |
| `GET /templates/{id}/versions/{v}/form-schema` | any (approved only for D) | Compiled form schema for the form engine |
| `POST /templates/{id}/versions/{v}/transitions` | T (submit), R (approve/reject) | Body `{ "to": "under_review" \| "approved" \| "draft" \| "retired", "comment": "" }` |
| `GET /templates/{id}/versions/{a}/diff/{b}` | T, R | Paragraph-level diff (later phase) |

### 2.5 Parties, properties, matters
| Method and path | Roles | Purpose |
|---|---|---|
| `GET /parties?q=...` | A, R, D | Trigram search by name in any language |
| `POST /parties` / `GET /parties/{id}` / `PATCH /parties/{id}` | A, R, D | CRUD; PATCH needs `If-Match`; creates a `party_versions` row |
| `GET /properties?q=...` / `POST /properties` / `GET` / `PATCH` | A, R, D | Same pattern |
| `POST /matters` / `GET /matters` / `GET /matters/{id}` | A, R, D | Group documents; drafters see assigned matters |
| `PUT /matters/{id}/parties` | A, D | Attach parties with roles |

### 2.6 Documents
| Method and path | Roles | Purpose |
|---|---|---|
| `POST /documents/validate` | D, R | Validate and compute derived fields without generating. Returns errors, warnings, derived values |
| `POST /documents` | D, R | Create generation job (requires `Idempotency-Key`). Returns `202` with `job` and `document` ids |
| `GET /jobs/{id}` | owner, R, A | Poll pipeline state |
| `GET /documents` | scoped | History; filters `matter_id`, `doc_type`, `language`, `status`, date range, `q` |
| `GET /documents/{id}` | scoped | Metadata, template version, status, review trail |
| `GET /documents/{id}/download?format=docx\|pdf` | scoped | Returns a **short-lived signed URL** (60 s) |
| `POST /documents/{id}/regenerate` | D, R | New version using the same snapshot and chosen template version |
| `POST /documents/{id}/reviews` | R | Body `{ "decision": "reviewed" \| "finalised" \| "changes_requested", "checklist": {}, "comment": "" }` |
| `POST /documents/{id}/portal-sheet` | D, R | Generates portal-ready party/property text (later phase) |
| `DELETE /documents/{id}` | A | Soft delete (finalised documents cannot be deleted) |

### 2.7 Admin and reference
| Method and path | Roles | Purpose |
|---|---|---|
| `GET /audit?entity=&entity_id=&cursor=` | A | Audit events; `GET /audit/verify` checks the hash chain |
| `GET /reference/zone-sheets?q=<village>` | any | Zone-map sheet lookup (later phase) |
| `GET /health/live`, `GET /health/ready` | public (internal network) | Liveness; readiness checks DB, storage, converter |

## 3. Key payloads

### 3.1 `POST /documents/validate`
```json
{
  "template_version_id": "0192...",
  "language": "mr",
  "data": {
    "parties": { "seller": [{ "party_id": "0192...", "overrides": {} }], "buyer": [] },
    "property": { "property_id": "0192...", "overrides": {} },
    "financial": {
      "total_consideration": "1310000.00",
      "installments": [{ "date": "2026-11-01", "mode": "cheque", "instrument_no": "000123", "bank": "XYZ Bank", "amount": "500000.00" }]
    },
    "witnesses": [{ "party_id": "0192..." }, { "party_id": "0193..." }]
  }
}
```
Response `200`:
```json
{
  "valid": false,
  "errors": [{ "path": "financial.installments", "code": "SUM_MISMATCH", "message": "Instalments total 500000.00; consideration is 1310000.00." }],
  "warnings": [{ "rule": "witness_min_two", "message": "..." }],
  "derived": { "financial.balance": "810000.00", "financial.total_in_words": "..." },
  "leftover_data": []
}
```

### 3.2 `POST /documents`
Headers: `Idempotency-Key: <uuid>`, `X-CSRF-Token: <token>`. Body as above. Response `202`:
```json
{ "document_id": "0194...", "job": { "id": "0195...", "state": "REQUESTED" } }
```
Poll `GET /jobs/{id}`:
```json
{ "id": "0195...", "state": "COMPLETED", "status": "succeeded",
  "document_id": "0194...", "outputs": { "docx": true, "pdf": false } }
```
Failure example:
```json
{ "id": "0195...", "state": "RENDERED", "status": "failed", "retryable": true,
  "error": { "code": "CONVERTER_TIMEOUT", "message": "PDF conversion timed out.", "correlation_id": "01HX..." } }
```

### 3.3 Template version upload (multipart)
Fields: `file` (DOCX, limit 5 MB), `manifest` (JSON). Response `201` with `lint_report`:
```json
{ "version": 3, "status": "draft",
  "lint_report": { "errors": [], "warnings": [{ "code": "UNUSED_FIELD", "path": "property.parking" }],
                   "leftover_data": [], "fonts": ["Noto Serif Devanagari"] } }
```

### 3.5 Administration & Health Endpoints
- `GET /api/v1/admin/users`: List tenant user accounts, active status, role, and MFA state.
- `POST /api/v1/admin/users/{user_id}/status`: Enable/disable user access.
- `GET /api/v1/admin/roles`: Authoritative RBAC matrix and separation-of-duties rules.
- `GET /api/v1/admin/audit`: SHA-256 hash-chained statutory audit trail events and chain integrity status.
- `GET /api/v1/admin/system-health`: Telemetry for API server, database pooling, document storage, and worker queues.
- `GET /api/v1/advisory/rules`: Statutory compliance rules catalog (TDS 194-IA, PAN Form 60, Agri Section 63, MahaRERA).
- `GET /api/v1/templates/{template_id}/manifest`: Raw manifest JSON schema for template studio and dynamic form configuration.

## 4. Authorisation matrix (summary)

| Resource and action | A | T | R | D |
|---|---|---|---|---|
| Manage users, settings, audit | yes | no | no | no |
| Create/upload template versions | no | yes | no | no |
| Approve template version | no | no | yes | no |
| Create document | yes | no | yes | yes |
| View documents | all | no | all | assigned or own |
| Review/finalise document | no | no | yes | no |
| Delete (soft) document | yes (not finalised) | no | no | no |

The matrix is implemented once as `authorize(actor, action, resource)` and tested as a table in `tests/api/test_authorization_matrix.py`.

## 5. Contract and quality
- OpenAPI schema committed at `backend/openapi.json` on every change; CI diffs it and fails on unreviewed breaking changes.
- Schemathesis fuzzes every endpoint in CI (including auth failures).
- Every endpoint has: success test, validation-failure test, unauthorised test, cross-tenant test (expects `404`), and an idempotency test where applicable.
- Responses never include password hashes, MFA secrets, ciphertext, blind indexes or session hashes.
- **No endpoint accepts a file path or URL to fetch.** Downloads use signed URLs generated server-side.
